# Deployment Guide

This project ships as a **fully local, reproducible analytics platform**.
There is **no live cloud deployment** in this repository; this guide documents
exactly how to run everything yourself and how the app/API would be deployed
on a cloud platform if you choose to.

Everything below has been run and verified on the local machine used to build
the project (Python 3.12+, PostgreSQL, Windows/Linux/macOS).

---

## 1. Local run (recommended)

### Prerequisites
- Python 3.12+
- PostgreSQL 13+ running locally with a database `retail_analysis`
- The cleaned dataset at `data/cleaned_retail_data.csv`
  (generated by `pipeline/run_pipeline.py`, or restored from a build)

### Setup

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux/macOS

pip install -r requirements.txt
pip install -r sql/requirements.txt

cp .env.example .env            # then edit DATABASE_URL
```

### Full pipeline (raw CSV -> PostgreSQL -> Power BI dataset + ML model)

```bash
python pipeline/run_pipeline.py      # cleans, loads DB, SQL analytics, PBI dataset, validates
python pipeline/run_ml.py            # trains the Phase 6 model family
python pipeline/run_ml_tune.py       # hyperparameter tuning -> final tuned model (logistic C=0.1)
```

### Export the final model (used by demo + API)

```bash
python pipeline/model_export.py
# writes models/churn_model.joblib + models/model_metadata.json
```

### Run the interactive demo

```bash
streamlit run app/churn_demo.py
# http://localhost:8501
```

### Run the prediction API

```bash
uvicorn api.main:app --host 0.0.0.0 --port 8000
# http://localhost:8000/docs  (Swagger UI)
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"features": {"recency_days": 120, "active_months": 2, "frequency": 2}}'
```

### Data quality / monitoring report

```bash
python reports/generate_data_quality_report.py   # needs DATABASE_URL for reconciliation
```

## 2. Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | yes (pipeline) | `postgresql://user:pass@host:5432/retail_analysis` |
| `INPUT_DATA_PATH` | no | override raw CSV path |
| `OUTPUT_DIR` | no | where pipeline manifests/reports are written (default `<repo>/reports`) |
| `PIPELINE_TEMP_DIR` | no | heavy temp work area (default system temp) |

**Never commit a real `.env`.** Use `.env.example` as the template.

## 3. Cloud deployment (how it *would* be done)

### Streamlit app
1. Push the repo (excluding `data/`, `models/`, `.env`).
2. On **Streamlit Community Cloud** or **Render**: point at `app/churn_demo.py`.
3. Provide env vars (see above) and run `python pipeline/model_export.py`
   as a build step, **or** pre-export the model and store it in an object store
   the app downloads on startup (the app falls back to training on first load).
4. No persistent storage is needed for the demo — it only reads the model.

### FastAPI
1. Build a container: `Dockerfile` (included below).
2. Deploy to any container host (Render, Railway, AWS ECS/Fargate, GCP Cloud
   Run).
3. `POST /predict` is stateless; scale horizontally.
4. Add an API key / OAuth proxy in front of `POST /predict` if exposing
   publicly (not implemented here by design — this is a portfolio project).

### Database
- Hosted Postgres (RDS/Cloud SQL/Neon/Supabase) with `DATABASE_URL` set.
- The pipeline is **idempotent-ish**: it reloads tables on each run; schedule
  it via cron / GitHub Actions (see `full-pipeline.yml`).

## 4. Dockerfile (API)

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt sql/requirements.txt ./
RUN pip install -r requirements.txt -r sql/requirements.txt
COPY . .
RUN python pipeline/model_export.py
EXPOSE 8000
CMD ["uvicorn", "api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

---

## 5. Honest limitations
- This repository has **no live deployment running**; the Dockerfile and
  instructions are provided as ready-to-use, but untested-on-cloud artifacts.
- `data/cleaned_retail_data.csv` (527,390 rows) is **gitignored**; any
  deployment must restore it or re-run `run_pipeline.py` first.
- The model artifact (`models/`) is gitignored and regenerated via
  `pipeline/model_export.py`.
- The demo is interactive but stateless — it does not persist user sessions.
